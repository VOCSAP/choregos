# Prosopon contract

Each requirement has a stable identifier and a matching `claude plugin test` case.

**Scope.** R1, R2, R3, R5 and R8 constrain what Prosopon adds or creates around the agent's text: the frames, their titles, the turn rule and any link it builds. The agent's Markdown passes through unchanged and would render the same in Claude Code's stock renderer, so these rules do not inspect it. R4 is the exception: it reads the agent's content. In M0 the dimmed summary line (`dim`) keeps the stock renderer until L2's differential capture of the stock and plugin renders, because its indentation changes where lines wrap.

- **R1** -- A frame added by Prosopon uses only `┌┐└┘─│`; Prosopon adds no round-corner glyph `╭╮╰╯`.
- **R2** -- Prosopon adds no line matching the numbered picker cue `^\s*❯\s+\d+\.`.
- **R3** -- Prosopon adds no line exactly `columns` wide made only of `─`, bare or with a central label.
- **R4** -- A short limit or quota message (at most 400 characters and 3 lines, holding `limit`, `reset`, `quota`, `overloaded` or `usage`) remains in Claude Code's stock renderer.
- **R5** -- Prosopon adds no spinner glyph and no spinner-row cue, including the ASCII `*` frame followed by a verb and an ellipsis.
- **R6** -- Layout support requires `SessionVersion.base` to be a release `MAJOR.MINOR.PATCH` at or above the minimum supported version (`2.1.303`), compared numerically component by component; an absent, `-dev`, unreadable or older version uses the stock renderer.
- **R7** -- Any malformed layout input or rendering error uses the stock renderer. A text Prosopon draws itself, a short assistant note or a framed prompt, is drawn only when it holds no character Claude Code refuses in a `Text` or `Markdown` string: a C0 control other than tab, LF and CR, DEL, a C1 control, an isolated surrogate, U+10EEEE, or U+2800 followed by a combining mark. Otherwise `next(e)` draws it, with no character removed. Prosopon performs no network or process access and only permits filesystem existence checks when such checks are introduced.
- **R8** -- Prosopon creates no link of its own in M0. A link it creates may use only `http:`, `https:`, or `file:`, is at most 2048 characters, defines no plugin-specific scheme, and never executes while read.
- **R9** -- Prosopon frames an assistant block around what `next(e)` resolves to and never redraws the agent's text itself, so a rewrite made by a hook above or beneath it (Mitos's links) survives whichever order the plugins load in. A summary block and a message R4 keeps stock are passed on to `next(e)` unframed.
- **R10** -- A user message is framed only when `origin.kind` is `composer`, its text is not blank, the surface is the terminal and the width is at least 40 columns; a task notification, a peer or channel message, a bridge or SDK turn, a missing or malformed origin keeps the stock renderer. The user frame title is `user_label` when it is a non-empty Unicode string of at most 20 code points containing no Cc or Cs character and no bidi control among U+061C, U+200E-U+200F, U+202A-U+202E, U+2066-U+2069; otherwise it is `You` or `Vous`, chosen by `labels`, with unknown values meaning `You`. Its title box is constrained between the frame borders and truncates at its end. `Claude` titles an assistant frame. `user_color` and `assistant_color` take a Claude Code theme key, a `#rrggbb`, or an English color name from a closed list (red, orange, yellow, green, cyan, blue, purple, magenta, pink, gray, grey, white, black), case ignored, resolved to a fixed `#rrggbb`; a theme key and a `#rrggbb` are taken first and as written, and any other value uses `suggestion` or `claude`.
- **R11** -- The turn rule is drawn only for a non-blank `word` and a finite, non-negative `durationMs`, outside the expanded view and when the row is not waiting on background agents. It is at most `columns - 2` code points long (no display-width measure is taken), starts with `──`, and carries no spinner glyph and no spinner-row cue.
- **R12** -- Prosopon redraws only a terminal `ToolUse` header for a non-running, non-errored, non-interrupted, non-expanded `Bash` call on a supported layout. It redraws a command only when it is non-empty printable ASCII of at most 300 UTF-16 code units and its custom wrapping uses no more than five header rows; these bounds wrapping work, and ASCII code-unit widths equal terminal-cell widths. It preserves the native one-row blank margin above the header. Its `● ` keeps the `success` colour, its `Bash(argument)` detail is dim, and wrapped detail has a six-column continuation indent. It redraws an `Edit` header as `Update(path)` and a `Write` header as `Write(path)`, the same way, only when `file_path` lies under `$.session.cwd()` segment by segment with no empty, `.` or `..` segment, and the path relative to it is non-empty printable ASCII of at most 40 characters, written with `\` under a drive-letter session directory and `/` otherwise, and the header fits on one row. A file elsewhere, which the native header shows as given, a drive letter cased differently, or a failing `session.cwd` calls `next(e)` unchanged. An unsupported tool, malformed or unsafe input, inactive layout, render error, or any other state calls `next(e)` unchanged. Results, diffs and tool groups are not redrawn.

# Mitos contract

Mitos rewrites a bare file path of an assistant reply into a Markdown link `[path](file:///...)` and passes the text on with `next`; it draws nothing itself. R4, R6 (capability `links`), R7 and R8 apply to Mitos as written above, with Mitos in place of Prosopon; R8 holds for every link Mitos creates. Each requirement below has a matching `claude plugin test` case.

- **MT1** -- Mitos links only an existing regular file reached through no symbolic link or junction: each path component is checked on its own, the walk stops at the first link, and nothing beneath that link is checked, so no path through a link to a network share is ever opened.
- **MT2** -- A network or device spelling (`\\`, `//`, `\\?\`, `\\.\`), a drive-relative path, an alternate data stream or a control character is never linked and never checked on disk.
- **MT3** -- Only extensions in the `allowed_extensions` option are linked; the manifest holds the default list, and a list set by the user replaces it. `exe`, `bat`, `cmd`, `ps1`, `psm1`, `msi`, `com`, `scr`, `vbs`, `hta`, `lnk`, `url`, `sh`, `reg`, `jar`, `appref-ms`, `js`, `jse`, `vbe`, `wsf`, `wsh`, `msc`, `cpl`, `pif`, `chm`, `scf`, `settingcontent-ms`, `application` and `gadget` are never linked, whatever the option holds; a `.js` path is therefore not clickable outside Kory.
- **MT4** -- The target is `file:///` followed by the absolute path with `/` separators, every character outside `A-Z a-z 0-9 - . _ ~ /` (and the drive colon) percent-encoded as UTF-8, and at most 2048 characters once encoded. A `:line` suffix stays in the label and never reaches the target.
- **MT5** -- Fenced code, inline code, existing links and images, autolinks and URLs are left untouched, so a second pass changes nothing.
- **MT6** -- At most 32 distinct paths are checked in one message; a reply over 64 KiB is passed on unchanged, and a run of non-blank characters longer than 2048 is not scanned.

# Thalpos contract

Thalpos keeps the prompt cache of the main conversation warm for a bounded period the operator starts with `/keep-warm`. It asks one tool-less question over the conversation with `$.model.fork` and discards the reply, so the conversation gains no turn. It assumes a one-hour cache lifetime. Each requirement below has a matching `claude plugin test` case, run on a mocked clock.

- **KW1** -- Nothing runs before `/keep-warm start`: no timer, no fork, no status line and no stored period exist until then; only the time of the latest request is kept (KW4). The command itself is registered at session start.
- **KW2** -- `start` without a duration means 3 hours; `start <h>` takes a positive number of hours (`5`, `5h`, `1.5h`). A duration under one hour, non-positive, unreadable or above the `max_hours` option (default 12) is refused with the usage line and changes nothing.
- **KW3** -- `start` while active replaces the deadline with now plus the new duration, keeps the time of the next ping or retry, and never stacks a second timer.
- **KW4** -- A ping is sent 50 minutes after the latest request of the main thread: a `turn.complete` with no `agentId`, or a ping. A subagent's `turn.complete` re-arms nothing. The time of the latest request (main `turn.complete` or ping) is kept even while inactive, so `start` counts the 50 minutes from it, not from the command; with no request seen since the plugin loaded, the command's time stands in. A cache known to be cold (59 minutes or more since the latest request) is never pinged; the plugin waits for the next turn.
- **KW5** -- No ping is sent at or after the deadline. On reaching it, the timers are cancelled, the status line is cleared and one toast says the period ended.
- **KW6** -- `stop` cancels the timers, clears the status line and keeps no deadline; `stop` while inactive answers that nothing was active.
- **KW7** -- A ping that answers but reads nothing, or writes at least a tenth of what it reads, means the cache was cold: the plugin stops as in KW6 and one toast says why. An `api-error` with status 429, 529 or 5xx is retried after 1, 2 then 4 minutes, only while the retry lands before the deadline and before the 59th minute since the latest request; any other failure, or a retry that cannot land in time, stops as in KW6 with one toast. `nothing-to-fork` sends nothing, stops nothing and waits for the next `turn.complete`.
- **KW8** -- `status` gives the deadline, the next ping time, the ping count and the summed `cache_read_input_tokens` and `cache_creation_input_tokens` of the pings.
- **KW9** -- A reload during an active period keeps the deadline and re-arms the timers from `$.state`; a reload after the deadline starts nothing. A stored value of an unknown shape is ignored.
- **KW10** -- The plugin uses `$.model.fork`, `$.clock`, `$.state`, `$.ui.status`, `$.ui.toast`, `$.ui.log` (debug only), `$.command.register` and `$.session.version`, and nothing else: no network, file or process access, and nothing written to the transcript. Any exception in a hook leaves the event to the stock behaviour, and an unsupported release or a development build registers nothing.
